# Исправление блокировки UI из-за недоступной сети

## Проблема
Когда интернет есть, но SoundCloud заблокирован (или любой другой API недоступен), приложение блокируется и перестаёт реагировать на кнопки, ползунок не работает.

## Причины
1. **ImageCacheService пытался скачать обложки** - RNFS.downloadFile() блокирует UI при network issues
2. **LibraryContext делал массовую валидацию при старте** - вызывал `RNFS.exists()` для всех треков
3. **HomeScreen и LibraryScreen валидировали треки** - вызывали `downloadService.getDownloadedTrackPath()` для каждого трека
4. **Все эти операции блокировали main thread** даже с async/await

## Решение

### 1. ImageCacheService - РАДИКАЛЬНОЕ решение
**Полностью отключили загрузку новых изображений**:
- ✅ Если изображение в кэше → показываем
- ✅ Если изображения НЕТ в кэше → **НЕ скачиваем**, просто показываем пустой View
- ✅ Никаких сетевых запросов для изображений во время работы приложения

**Результат**: UI никогда не блокируется на загрузке обложек

### 2. CachedImage - дополнительная защита
Добавлен Promise.race с 3-секундным таймаутом на вызов getCachedImage()

### 3. LibraryContext - ОТКЛЮЧЕНА автоматическая синхронизация
**Отключены при старте:**
- ✅ `validateAndSyncFilePaths()` - проверка всех треков
- ✅ `syncLikedSongs()` - синхронизация лайкнутых
- ✅ `syncRecentlyPlayed()` - синхронизация недавних

**Почему**: Каждая функция вызывала `RNFS.exists()` для всех треков, блокируя UI на несколько секунд

### 4. HomeScreen - простая фильтрация
Вместо валидации файлов через `downloadService.getDownloadedTrackPath()`:
- ✅ Просто фильтруем треки по наличию `filePath`
- ✅ Мгновенный рендеринг без блокировок

### 5. LibraryScreen - простая фильтрация
Аналогично HomeScreen - только проверка `track.filePath`, без обращения к файловой системе

## Когда обложки загружаются?
Обложки теперь загружаются только:
1. **При первом поиске трека** (когда интернет работает)
2. **При скачивании трека** (в этот момент обложка кэшируется)

После этого обложки берутся из кэша и никакие сетевые запросы не делаются.

## Результат
✅ **Приложение запускается МГНОВЕННО** - нет задержек при старте
✅ **UI всегда отзывчив** - никаких блокировок main thread
✅ **Работает плавно с заблокированным SoundCloud**
✅ **Ползунок, кнопки, навигация - мгновенная реакция**
✅ **Скачанные треки воспроизводятся без задержек**
✅ **Нет проверок файловой системы при загрузке**

## Компромисс
⚠️ **Новые обложки не загружаются автоматически**
- Обложки загружаются только при скачивании трека
- После этого берутся из кэша

⚠️ **Нет автоматической синхронизации filePath при старте**
- Если трек в базе без filePath, он не отобразится
- Решение: при скачивании filePath всегда сохраняется
- Если всё равно нужна синхронизация - можно вызвать вручную

**Это намного лучше, чем зависающее приложение!**

## Включение обратно загрузки обложек
Если в будущем захотите включить обратно:
1. Откройте `src/services/ImageCacheService.ts`
2. Раскомментируйте код между `/* */`
3. Удалите строку `return '';` после проверки кэша
